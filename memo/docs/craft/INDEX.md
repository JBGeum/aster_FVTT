# Aster 공방(Craft) 스킬 시스템 — 구현 문서 세트 (INDEX)

> Foundry VTT V13 / ApplicationV2 기준. Claude Code에 STEP 단위로 넘겨 구현.
> "craft"는 제작이 아니라 **공방**의 의미. 고정 스킬트리에서 체크로 취득 관리.
> 선행: 그리드 인벤토리 구현 완료 후 진행. `actor-sheet-parts-design.md`의 `craft` 탭에 연결.

---

## 한 줄 정의

카테고리별로 **고정된** 스킬 노드(레벨/비용/선행관계)를 시트에 항상 같은 형태로 그리고,
플레이어가 **체크로 취득**한다. 선행 미취득 시 취득 거부+알람. 비용(마테리얼/아스테르) **합계**가 보유량을 넘으면 취득 거부 + 이미 초과면 빨강 표시.

---

## 확정 명세 (모든 결정 완료)

| 항목           | 결정                                                                                                             |
| -------------- | ---------------------------------------------------------------------------------------------------------------- |
| 트리 구조      | **정적 정의**(코드/JSON 고정). 동적 생성·편집 없음                                                               |
| 취득 저장      | 액터에 취득 스킬 id 집합(boolean 맵)                                                                             |
| 선행 검사      | 스킬의 `requires` 선행 id가 **모두** 취득돼야 체크 가능. 아니면 거부+알람                                        |
| 분기           | 선행 1개 공유로 표현(여러 스킬이 같은 `requires`). 로직 동일                                                     |
| 비용 검사      | 취득 스킬들의 **마테리얼 합 / 아스테르 합** ≤ 보유량. 임의 비용은 아스테르 **총합**에 단순 합산                  |
| 비용 검사 시점 | **결합**: ① 취득 시점 — 합계 초과면 거부 ② 상시 — 이미 초과면 빨강 표시 (같은 함수 재사용)                       |
| 임의 아스테르  | 색 배분 없이 총합으로만. 표시는 "임의 N". **종류 제약(2종류 2개씩 등)은 미구현(확장)**                           |
| 해제           | 개별 해제 허용하되 **선행 해제는 거부**(후속이 취득돼 있으면 막음) + **전체 초기화** 버튼                        |
| 비용 자원 출처 | 마테리얼=`system.material`(또는 인벤토리), 아스테르=`system.aster.*`. 공방은 **참조만**(차감 안 함, 합계 비교만) |

> 핵심: 자원을 차감하지 않는다. "취득 스킬 비용 합 ≤ 보유 자원"을 그때그때 비교만 한다.
> 자원은 시나리오 클리어·정동판정으로 별도 증감. 공방은 읽기만.

## STEP 구성

| STEP | 문서                   | 내용                                                                            | 도구                 |
| ---- | ---------------------- | ------------------------------------------------------------------------------- | -------------------- |
| 1    | `STEP1_tree_data.md`   | 정적 트리 정의(노드/비용/선행 표 — **Sch가 채울 빈칸 포함**) + 액터 취득 스키마 | Claude Code + Sch    |
| 2    | `STEP2_logic.md`       | 선행 검사 + 비용 합계 검사 순수 함수 + Vitest                                   | Claude Code          |
| 3    | `STEP3_render.md`      | 고정 트리 렌더(카테고리/노드/체크박스/비용/연결선)                              | Claude Code → Cursor |
| 4    | `STEP4_interaction.md` | 체크 취득/해제/거부 알람/전체 초기화 + 초과 빨강 표시                           | Claude Code → Cursor |

### 진행 원칙

- 한 STEP씩. 완료 = `lint`/`typecheck`/`build`(STEP2는 `test`) 통과 후 커밋.
- 트리 구조가 고정이라 인벤토리보다 단순. 좌표/드래그 없음.
- **STEP1의 트리 정의 표는 Sch가 게임 규칙대로 채워야 함**(이미지에서 비용·레벨은 초안 제공, 선행 연결·가려진 카테고리는 빈칸).

### 커밋 메시지 예시

```
feat(craft): add static skill tree definition and acquisition schema
feat(craft): add prerequisite and cost-sum checks with tests
feat(craft): render fixed skill tree with checkboxes and links
feat(craft): add skill toggle, prereq block, and reset
```

## 이미지에서 읽은 카테고리 (STEP1 초안 입력)

- **약 제조:** 가마솥 Lv.1~3, 약연 Lv.1~2, 물레방아 Lv.1~2
- **부적 만들기:** 조각대 Lv.1~3, 반짇고리 Lv.1~3
- **요리:** (이미지 하단 잘림 — Sch 보완 필요)
- **사역마:** 까마귀/부엉이/뱀/생쥐/개구리/검은고양이 (각 단일, ◇임의 4)
- **가구·기타:** 소중한 물건 Lv.1~5, 그네 Lv.1~3, 책상 Lv.1~3

> 노드 비용(◆마테리얼/◇아스테르 적·청·녹·황)은 STEP1 표에 이미지값 초안 기입. 가려지거나 불명확한 값은 빈칸.

## ⚠️ 미구현(확장) 표시

- 임의 아스테르 **색 배분 입력** 및 **종류 제약**("2종류 2개씩") — 기본은 총합만. 필요 시 후속.
- 사역마/가구가 단순 스킬인지 별도 효과(인벤토리 COMPA 등)와 연동되는지 — 추후.
- 스킬 효과의 다른 스탯 반영(예: 창고 용량 = 특정 스킬) — 별도 작업. 본 세트는 "취득 관리"까지만.
